## Selection and usefulness

Every current lesson has at least one concept where a worked structure or state trace helps, so no entire lesson is classified as not useful for visualization. The other 702 paragraphs intentionally do **not** receive automatically generated, repetitive diagrams. This is a selective first pass, not a claim that those paragraphs could never benefit from a visual.

Useful representations include actual array positions and selected slices, before/after object identities, request-order races, validation branches, SQL joined rows and grouped contributions, CSS box dimensions and track-space arithmetic, module/file relationships, and the exact input/output transitions in the lesson examples. These are not generated by copying generic “input → process → output” labels or extracting a first sentence.

Concepts that do not need a separate visual are not forced into one. For example, the toolkit testing guide explicitly says that concurrency testing is not useful for its pure stateless clamp function. Caveats distinguish conceptual examples from real network requests, browser fixtures from local execution, type checks from runtime validation, and shallow copies from independent nested objects.

The Python Basics guide is a trace of the existing Pepper introduction. It is separate from the more detailed concept lab, so lesson-level guide coverage should not be presented as equivalent to the concept lab's per-concept interactions.

## Data contracts

`LessonVisual` exports an ID, one of five presentation kinds, a title, a concrete setup, 3–5 worked items, a takeaway, an optional limitation, and the selected paragraph index. `getLessonVisual(unitId, paragraph)` returns a guide only for its authored page and returns `undefined` for unrelated or unknown pages.

`getLessonHeadings(lessonId)` returns a copy of the authored headings array. Array positions match the unchanged original explanation positions. Unknown IDs return an empty array. This lets the shared contents UI use meaningful labels while preserving existing deep-link page indexes.

## Verification

Run:

- `node tests/lesson-visuals.mjs`
- `npx tsc --noEmit --target es2022 --module esnext --moduleResolution bundler --skipLibCheck lib/lesson-visuals.ts lib/lesson-headings.ts`
- `npx eslint lib/lesson-visuals.ts lib/lesson-headings.ts tests/lesson-visuals.mjs`

The content test loads the real TypeScript modules in memory, compares their IDs with both lesson and catalog sources, checks exact counts and page bounds, verifies page-specific lookup and unknown-ID behavior, requires bounded non-placeholder example text, checks safe display strings, and protects key accuracy details. It also validates all 818 titles against the source paragraph counts and protects the seven requested Python Basics titles.

Content checks do not replace browser accessibility testing, responsive-layout inspection, or running the original projects in their required language environments. Separate UI and lesson-content tests own those checks.

Six additional worked-example pages now have primary interactive scenes: python-03 section 3 (room and reminder), python-04 section 3 (calendar visits), python-05 section 5 (collector tray), python-08 section 3 (recipe-scaling workbench), python-15 section 3 (demand/bookmark station), and python-23 section 3 (quoted CSV parcels). The other useful technical diagrams remain valid explanatory visuals.
