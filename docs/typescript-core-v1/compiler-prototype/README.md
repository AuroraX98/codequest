# TypeScript compiler-only assessment prototype

Staged only: no canonical content, runtime or progress changes.

The actual TypeScript 5.9.3 compiler runs the production strict ES2015 library configuration. Learner compilation must succeed first. Separate block-scoped assertion files test positive public relationships or intended negative diagnostics; only learner source is transpiled and executed. Negative checks require their assertion filename, source range and recorded diagnostic code. Exhaustiveness variants extend the authored union through the TypeScript AST and require a clean parsed mutation plus a coverage diagnostic inside the named handler. Function declarations and named arrow/function-expression handlers are supported.

Contract-assessed exercises explicitly disallow real parsed diagnostic-suppression directives. Ordinary comments mentioning those words do not count. No lesson teaching diagnostic directives will silently inherit this policy; such a lesson would need separately scoped fixtures. Equivalent safe type constructions are accepted, not graded by keyword spelling.

`prove.cjs` / `proof-results.json`: 34 native architecture tests pass, including all 14 existing runnable solutions, accepted equivalents, discovered weak generic/tuple variants, normal bidirectional relationships, directive handling, helper isolation, new-variant exhaustiveness and an assertion execution sentinel. These are finite assessment examples, not proof against every possible submission.

`make-browser.cjs` constructs an isolated copy of the actual production frame with the additive compiler engine and message fields. CSP and downloaded-asset bridge are unchanged. `make-exact-runner.cjs` uses the exact production runProject lifecycle; only offline storage adapters point to identical local vendor bytes. This preview has no accounts, student data, remote requests or deployment identity. Browser results remain pending until actually collected.

The production 25-second timer begins after static frame and vendor asset acquisition. The browser receipt will separately retain local asset acquisition time and total runProject time (including first acquisition), and cover worker compiler startup, library reads, all assertions and runtime checks. No budget increase is proposed. Later cancellation/timeout checks must use the unchanged production lifecycle, not infer them from a native compile.
